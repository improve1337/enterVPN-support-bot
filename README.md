# EnterVPN Support — бот поддержки

Отдельный Telegram-бот для обращений в поддержку EnterVPN. Пользователь пишет
сообщение — создаётся тикет, оператор отвечает прямо в чате. Основной бот
продажи подписок переводит сюда по кнопке «💬 Поддержка».

TypeScript + grammY + `node:sqlite` (Node.js ≥ 22.5). Long polling, входящие
порты не нужны.

## Запуск

```bash
npm install
cp .env.example .env      # Windows: copy .env.example .env
npm run dev               # tsx watch, автоперезапуск
```

Проверка, что всё поднялось: `http://127.0.0.1:3000/health`.

| Команда | Что делает |
|---|---|
| `npm run dev` | запуск с автоперезапуском (`tsx watch`) |
| `npm start` | однократный запуск (`tsx`) |
| `npm run build` | компиляция в `dist/` (`tsc`) |
| `npm run start:prod` | запуск собранного `dist/index.js` |
| `npm run typecheck` | проверка типов без сборки |

## Команды бота

| Команда | Кому | Что делает |
|---|---|---|
| `/start` | всем | приветствие с картинкой и меню |
| `/tickets` | всем | статус своих обращений |
| `/help` | всем | как это работает |
| `/admin` | админам | админ-панель |
| `/find <@username\|ID>` | админам | найти тикеты пользователя |
| `/close <@username\|ID>` | админам | закрыть открытый тикет |
| `/open <@username\|ID>` | админам | открыть закрытый тикет |

## Как работает обращение

1. Пользователь пишет сообщение — создаётся тикет, и оно уходит всем админам
   (заголовок с именем, @username и ID + копия самого сообщения).
2. Следующие сообщения добавляются в тот же тикет, пока он открыт.
3. Админ отвечает **ответом** на сообщение с обращением — текст уходит
   пользователю.
4. Админ закрывает тикет. Новое сообщение пользователя создаст новый.

## Админ-панель

Кнопка «🛠 Админка» в меню (видна только админам):

- **🎫 Открытые тикеты** — список и карточки, у каждой кнопка закрытия
- **🔎 Найти тикет** — по `@username` или Telegram ID
- **👥 Админы** — список, добавление по ID и снятие прав
- **📊 Статистика** — пользователи, тикеты, сообщения, админы

Админы из `ADMIN_IDS` неудаляемы: они остаются доступом, даже если база
обнулится. Назначенные через панель хранятся в базе.

## Переменные окружения

Обязательна только `BOT_TOKEN`.

| Переменная | Значение на хостинге | Зачем |
|---|---|---|
| `BOT_TOKEN` | токен от @BotFather | обязательно |
| `ADMIN_IDS` | ваш Telegram ID | доступ к админке |
| `BOT_USERNAME` | `EnterseviceSupport_bot` | показывается в текстах |
| `BRAND_NAME` | `EnterVPN` | название в интерфейсе |
| `NODE_ENV` | `production` | формат логов |
| `PORT` | `3000` | только для `/health` |
| `DATABASE_PATH` | `/app/data/support.db` | **иначе база теряется при передеплое** |
| `BANNER_PATH` | `/usr/src/app/welcomepic.png` | картинка на `/start` |
| `TELEGRAM_PROXY` | пусто | нужен, если `api.telegram.org` недоступен |

Файл `.env` на хостинг не заливать — он в `.dockerignore` и `.gitignore`.

## Картинка приветствия

`welcomepic.png` в корне проекта. Если файла нет, бот отправит обычный текст.
Заменить картинку — просто положить свой файл с тем же именем.

## Деплой на Bothost

1. Подключить репозиторий, ветка `main`.
2. Включить **«Использовать собственный Dockerfile»** — он уже в корне и
   написан под Bothost: `WORKDIR /usr/src/app` (вне `/app`), данные в
   `/app/data`, Node 24 внутри образа.
3. Порт в панели — `3000`.
4. Задать `ADMIN_IDS` в переменных окружения (`BOT_TOKEN` платформа подставит
   сама).
5. Проверить логи: `Telegram доступен` и `HTTP-сервер мониторинга запущен`.
6. Проверить `https://<домен>/health`.

Если в логах `Telegram Bot API недоступен` — у ноды российский IP. Включить в
профиле Bothost «Зарубежный IP для API и нейросетей» и задеплоить заново.

```
  telegram.ts     прокси, preflight, список команд
  logger.ts       pino + вырезание токена из логов
  chat-cleanup.ts удаление экранов прошлого шага
  ui/             тексты и клавиатуры
welcomepic.png    картинка приветствия
```
